# 류이어리

비공개 실시간 교환 일기장입니다.  
글과 그림으로 일상을 기록하고 실시간으로 공유합니다.

- 배포 주소: https://agreesin.github.io/ryuwithagree/

---

## 접근 권한

이 다이어리는 비공개로 운영됩니다.

- 구글 로그인이 필요합니다.
- 사전에 지정된 두 사용자 계정에만 Firestore 읽기 및 쓰기 권한이 부여됩니다.
- 권한이 없는 계정은 로그인해도 일기를 읽거나 쓸 수 없습니다.

---

## 현재 기능

- **구글 로그인**: 허가된 두 계정으로 안전하게 로그인 및 세션 유지
- **일기 작성 및 삭제**:
  - 글만 작성, 그림만 작성, 글과 그림 함께 작성 모두 지원
  - **오늘의 기분 이모지(😁🥰😭🤬🫪😴) 선택 기능**
  - **제목 미입력 시 'M/D 오늘의 일기' 자동 생성**
  - 작성자 본인이 쓴 글만 삭제 가능
  - 작성 일시 자동 기록 및 한국어 로케일 포맷 표시
- **그림판(드로잉)**:
  - 마우스 및 모바일 터치 드로잉 동시 지원
  - 펜(색상 선택, 굵기 3단계), 지우개, 전체 지우기
  - 스트로크 히스토리 기반 실행취소(Undo)
  - 고압축 이미지(WebP/JPEG) 데이터 저장
- **댓글 및 답글(대댓글)**: 각 일기 카드별 댓글 작성 및 인라인 답글(대댓글) 작성, **본인 작성 댓글/답글 수정 및 삭제 기능**, 실시간 계층형 표시
- **상단 공지사항**: 방문자 안내 및 사용자 간 공동 공지 등록·수정·삭제, 실시간 동기화
- **실시간 및 백그라운드 웹 푸시 알림**:
  - 앱 내 핑크 토스트 카드 및 탭 제목 깜빡임
  - iOS/Android PWA(홈 화면 추가) 및 브라우저 시스템 알림 지원 (OneSignal 연동)
- **닉네임 관리**: 관리자 권한을 통한 내 닉네임 및 상대방 닉네임 변경 (화면 및 기존 작성 글/댓글 일괄 동기화)
- **실시간 동기화**: 한 사람이 글/그림/댓글/공지를 작성하거나 닉네임을 변경하면 상대방 화면에 즉시 반영

## 파일 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대 마크업 (PWA 메타, 공지사항, 토스트, 로그인, 작성 폼, 일기 목록) |
| `style.css` | 핑크 톤 테마 스타일링, 토스트 알림, 공지사항 배너, 카드 레이아웃, 반응형 뷰 |
| `manifest.json` | PWA 웹 앱 매니페스트 (아이폰/안드로이드 홈 화면 설치용 메타데이터) |
| `OneSignalSDKWorker.js` | OneSignal 백그라운드 푸시 서비스 워커 |
| `app.js` | 앱 진입점. 각 모듈 초기화 및 이벤트 배선만 담당 |
| `notify.js` | OneSignal SDK, 브라우저 시스템 알림, 앱 내 핑크 토스트 및 백그라운드 푸시 발송 |
| `notice.js` | 상단 공지사항 렌더링, 접기/펼치기, 공지 작성/수정/삭제 이벤트 처리 |
| `auth.js` | 구글 로그인/로그아웃 처리 및 데이터 실시간 구독 관리 |
| `profile.js` | 내 닉네임 및 친구 닉네임 변경 이벤트 처리 |
| `entries.js` | 일기 작성 폼 입력 검증, 그림판 토글 및 저장 핸들링 |
| `draw.js` | 캔버스 드로잉(Pointer Events), 스트로크 Undo, 이미지 고압축 내보내기 |
| `entry-card.js` | 일기 카드 1건 DOM 생성 (삭제, 본문, 그림, 댓글 섹션 조립) |
| `comments.js` | 개별 일기 카드의 댓글 및 답글(대댓글) 계층형 렌더링, 인라인 답글 폼 배선 |
| `render.js` | Firestore 일기 목록을 받아 목록 화면 갱신 |
| `state.js` | 전역 공유 상태(현재 사용자, 프로필 캐시) 및 관리자 권한 검사 |
| `store.js` | Firebase SDK 연동 배관 (Firestore CRUD, Auth, 실시간 onSnapshot) |
| `ui.js` | 공통 에러 배너 표시 및 숨김 제어 |

## 로컬 실행 방법

이 프로젝트는 순수 ES 모듈(`type="module"`)을 사용합니다.  
브라우저 보안 정책상 `index.html`을 더블클릭(`file://`)하여 열면 동작하지 않습니다.

로컬에서 테스트하려면 로컬 웹 서버를 실행해야 합니다:

```bash
# Python 3 내장 서버 실행 (프로젝트 루트 디렉터리)
python -m http.server 8000
```

서버 실행 후 브라우저에서 `http://localhost:8000` 으로 접속합니다.

## 협업 및 개발 규칙

> [!IMPORTANT]
> **개인정보 보호 및 완전 익명화 원칙 (AI 및 개발자 필독)**
> 이 저장소는 Public으로 공개되어 있으므로, **작업자가 누구인지 유추할 수 있는 일체의 개인정보를 코드, 주석, 문서, 기본 데이터에 절대 노출하지 않습니다.**
> 1. **실명 및 이메일 하드코딩 금지**: 소스코드, 주석, 커밋 메시지, 기본 데이터/문구에 작업자의 실명, 개인 이메일, 고유 닉네임을 일체 기재하지 않습니다.
> 2. **관계 유추 키워드 금지**: 작업자 간의 신원이나 관계를 유추할 수 있는 표현을 피하고, '사용자', '관리자', '참여자' 등 중립적인 용어를 사용합니다.
> 3. **AI 어시스턴트 필수 준수**: AI는 코드를 수정하거나 새 기능을 추가할 때 항상 이 익명화 원칙을 최우선으로 검증하고 준수해야 합니다.

1. **작업 시작 전 최신 코드 가져오기**:
   - `git pull origin main`
2. **`main` 브랜치 직접 푸시 금지**:
   - 기능 브랜치를 생성하여 작업한 뒤 PR을 올리고, 상대방이 검토 후 머지합니다.
3. **작은 단위 PR 유지**:
   - 기능 하나당 하나의 PR로 작게 나누어 충돌을 최소화합니다.
4. **Firestore 스키마 불변성 준수**:
   - 기존 필드명(`title`, `body`, `author`, `uid`, `createdAt`, `comments`, `image`)은 절대 이름 변경하거나 삭제하지 않습니다. 신규 필드 추가만 허용합니다.
   - 필드를 읽을 때는 필드가 존재하지 않을 수 있다고 가정하고 방어적으로 작성합니다.
5. **구조 변경 사전 합의**:
   - 파일 구조 변경이나 대규모 리팩터링은 반드시 사전 합의 후 단독 PR로 분리하여 진행합니다.
6. **동시 작업 충돌 방지**:
   - `entries.js`(작성)와 `entry-card.js`(렌더링)는 두 사람이 동시에 수정하지 않도록 사전에 역할을 분담합니다.

## 자주 나는 사고

| 증상 | 원인 | 조치 |
|---|---|---|
| `push`가 거부됨 (rejected) | 원격에 내가 모르는 커밋이 있음 | `git pull origin main` 후 다시 푸시 |
| `push`가 거부됨 (403) | 저장소 협업자 권한 없음 | GitHub 초대 수락 여부 확인 |
| `<<<<<<<` 충돌 표시 | 같은 파일의 같은 위치를 동시에 수정함 | 충돌 마커를 정리하고 올바른 코드를 남긴 뒤 커밋 |
| 상대 코드가 사라짐 | 브랜치 병합 과정에서 덮어씀 | `git log` 확인 후 직전 커밋으로 복구 |
| 일기가 안 보임 / 저장 실패 | 인터넷 연결 또는 Firebase 권한 문제 | F12 → Console 탭의 에러 메시지 확인 |
| 로컬에서 화면이 하얗게 나옴 | `file://` 경로로 직접 실행함 | `python -m http.server` 등 로컬 서버로 실행 |
